# `default-annotations-gen`

Generates a `default_annotations.gen.tf` for every Terraform module under a path,
binding a set of Scaleway annotation **values** to every `scaleway_*` resource in
that module.

You create the annotation **keys** and **values** yourself. This tool only generates
the `scaleway_annotations_binding` resources: for each `(value, target)` pair it emits
one binding, so **N values × M targets = N×M bindings**.

## How it works

- Walks `-path` recursively; every directory that directly contains at least one `.tf`
  file is treated as a Terraform module (hidden directories such as `.terraform` are
  skipped).
- For each module it collects every `scaleway_*` resource instance (the generated file
  itself is ignored).
  - **Values** = `scaleway_annotations_value` resources (auto-discovered) plus any
    explicit `-value` expressions.
  - **Targets** = every other `scaleway_*` resource (`scaleway_annotations_*` are
    excluded), each referenced by its `.srn`.
- Emits `default_annotations.gen.tf`, marked `# Code generated … DO NOT EDIT.`.
  Re-running is idempotent and safe.

## Usage

Run from the provider repo root:

```sh
# dry run — print the generated HCL to stdout
go run ./cmd/default-annotations-gen -path /path/to/your/modules

# write default_annotations.gen.tf into each module
go run ./cmd/default-annotations-gen -path /path/to/your/modules -write

# build a standalone binary
go build -o bin/default-annotations-gen ./cmd/default-annotations-gen
```

### Flags

| Flag            | Default                          | Description |
| --------------- | -------------------------------- | ----------- |
| `-path`         | *(required)*                       | Root directory to walk recursively. The tool exits if it is not set. |
| `-write`        | `false`                          | Write `default_annotations.gen.tf` into each module. Omit for a stdout dry-run. |
| `-check`        | `false`                          | Exit non-zero if any `default_annotations.gen.tf` is missing or out of date. Mutually exclusive with `-write`. |
| `-value`        | —                                | Explicit annotation value to bind (repeatable). A bare `type.name` is expanded to `.value_id`; anything with two or more dots is used verbatim. |
| `-inherit`      | `false`                          | Treat a module that declares `-inherit-var` as a **consumer** that reads its values from that variable. |
| `-inherit-var`  | `default_annotations_values`     | The variable (a `map(string)` of key → value_id) that carries inherited values. |

### Example output

```hcl
# Code generated by cmd/default-annotations-gen; DO NOT EDIT.
locals {
  annotations_values = {
    "scaleway_annotations_value.production.value_id" = scaleway_annotations_value.production.value_id
  }

  annotations_targets = {
    "scaleway_vpc.core"              = scaleway_vpc.core.srn
    "scaleway_vpc_private_network.app" = scaleway_vpc_private_network.app.srn
  }

  annotations_bindings = {
    for entry in flatten([
      for v_key, v_id in local.annotations_values :
      [
        for t_key, t_srn in local.annotations_targets :
        {
          key        = "${v_key}|${t_key}"
          value_id   = v_id
          target_srn = t_srn
        }
      ]
    ])
    : entry.key => {
      value_id   = entry.value_id
      target_srn = entry.target_srn
    }
  }
}

resource "scaleway_annotations_binding" "default_annotations" {
  for_each = local.annotations_bindings

  value_id   = each.value.value_id
  target_srn = each.value.target_srn
}
```

## Inheritance across modules

Terraform resource references are **module-scoped**: a module can only reference its own
resources, and two independent roots cannot see each other. To share one annotation value
across a parent and its children:

1. **Owner** (usually the root) declares the `scaleway_annotations_value` resource(s) and
   a map, e.g. `local.default_annotations_values = { environment = scaleway_annotations_value.production.value_id }`,
   and passes it down in each `module` block: `default_annotations_values = local.default_annotations_values`.
2. **Consumers** (children) declare `variable "default_annotations_values" { type = map(string) }`.
3. Run with `-inherit`: any module that declares that variable gets
   `annotations_values = var.default_annotations_values` instead of local value discovery.

The `for_each` keys stay plan-time-known (map key + target address), so this is valid even
though the `value_id`s are computed at apply time.

## Keeping the generated file in sync

`default_annotations.gen.tf` is a **snapshot**: the target list is enumerated at generation
time. Terraform has no way to reflect over "all of my resources" at plan time, so the tool
cannot discover new resources on its own.

| Change                          | Symptom |
| ------------------------------- | ------- |
| Add a `scaleway_*` resource     | **Silent** — it simply is not annotated until you regenerate. |
| Remove / rename a resource      | **Loud** — a stale `local` reference makes `terraform validate` fail. |

So: regenerate after any add / remove / rename of `scaleway_*` resources (or of annotation
values), and review the git diff of the generated file.

### Freshness check (`-check`)

To make it impossible to forget, gate on "the generated file is always up to date". The
`-check` flag regenerates each module in-memory and compares the result against the committed
`default_annotations.gen.tf`. A module is **stale** if its generated file is missing, differs,
or exists when nothing is expected. It prints each stale module and exits non-zero if any are
stale:

```sh
$ go run ./cmd/default-annotations-gen -inherit -check -path /path/to/your/modules
3 module(s) in sync, 0 skipped, 0 stale            # exit 0

$ # … add a scaleway_* resource to a module, then re-run:
stale: /path/to/your/modules/modules/compute
2 module(s) in sync, 0 skipped, 1 stale            # exit 1
```

This is reliable because the output is deterministic: targets are sorted and values are
de-duplicated by key, so the same input always yields the same bytes. Run the check with the
**same flags you generate with** (e.g. `-inherit`), otherwise the comparison always differs.
`-check` is mutually exclusive with `-write`.

### Automating

The tool has no built-in hooks; each of these just runs the two flags above. Pick whatever
fits the repo you use it in. If you install the tool as a binary instead of `go run`, swap
the command below for the binary path.

**Live file watcher** — auto-regenerate while you edit

Watch the module root and re-run with `-write` on every change. Use whichever watcher you
already have:

```sh
# watchexec (portable)
watchexec -w ./infra 'go run ./cmd/default-annotations-gen -inherit -write -path ./infra'

# entr (stdin-driven)
find ./infra -name '*.tf' -print0 | entr -c -d0 go run ./cmd/default-annotations-gen -inherit -write -path ./infra

# inotifywait (Linux) / fswatch (macOS)
inotifywait -mqr --format '%w%f' -e modify,create,delete,moved_to ./infra \
  | while read -r _; do go run ./cmd/default-annotations-gen -inherit -write -path ./infra; done
```

This makes the update automatic during development; commit the regenerated files as usual.

**Pre-commit hook** (`.pre-commit-config.yaml`) — gate on freshness

Fail fast when a `.tf` change would make the generated file stale:

```yaml
repos:
  - repo: local
    hooks:
      - id: default-annotations-check
        name: default-annotations-gen freshness
        entry: go run ./cmd/default-annotations-gen -inherit -check -path ./infra
        language: system
        pass_filenames: false
        files: '\.tf$'
```

To **auto-update** instead of failing, switch the entry to `-write` and re-stage the
generated files:

```yaml
      - id: default-annotations-update
        name: default-annotations-gen update
        entry: go run ./cmd/default-annotations-gen -inherit -write -path ./infra && git add -u '*.gen.tf'
        language: system
        pass_filenames: false
        files: '\.tf$'
```

**CI** (GitHub Actions or any runner) — required gate

Make `-check` a required status check so a stale file blocks the merge:

```yaml
- name: Check default_annotations.gen.tf freshness
  run: go run ./cmd/default-annotations-gen -inherit -check -path ./infra
```

## Known limitations

- Resources using `for_each` (or a non-literal `count`) are **not** auto-enumerated; the
  tool emits a `# NOTE: skipped …` comment for them.
- The tool assumes every target exposes `.srn`. A `scaleway_*` resource without `.srn`
  makes the generated file fail `terraform validate`.
- The owner→child wiring (`module "x" { default_annotations_values = … }`) and the
  `variable` / `local` declarations are **hand-written**; the tool only generates the
  binding files.
- The generated file reserves the local names `annotations_values`, `annotations_targets`,
  and `annotations_bindings` in every module it generates for. A hand-written `local` with
  any of those names in the same module will fail `terraform validate` ("Local value names
  must be unique"). Your own local can use any other name — e.g. `default_annotations_values`
  — as long as only the `module` argument is called `default_annotations_values` to match the
  child `variable`.
